The daemon refused the coder node at its `proc` capability check, before any podman invocation. No container
started and no `coder.spawned` event was journalled. The refusal names the capability but not the argv0 or path

## Open

- Whether the `proc` denial is the sandbox. `run_caps` (`crates/pii-server/src/engine/run_scope.rs:76`) grants
  `PROC` to every run, so the denial is probably the argv0 scope: the probe execs `/usr/bin/podman`, which is
  absent here, and the daemon's `proc` argv0 grant may not carry it. Confirming needs the denied argv0 in the
  journal, which today's refusal text does not include.
- Podman is not installed, so even a sandbox-clean daemon cannot pass M0 on this host. The spec's requirement
  1a (a container whose only action is `true`) is not what the coder node runs: the coder node appends its agent
  argv (`pi`) after the image, so the graph uses `agent = "pi"` with `container_image = "localhost/pii-agent:1"`.
- The graph writes into the daemon's graph directory; it is a new file, and the script moves any different
  earlier copy aside rather than overwriting it.
