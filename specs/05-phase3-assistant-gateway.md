# Spec: Phase 3 - Assistant / daemon, networking, workers, memory

## Overview

**Project**: <repo>
**Phase**: 3 - Assistant / gateway (daemon, networking, workers, layered memory)

**Spec of record**: `_docs/06-research/001-pii-architecture-plan.md` §"Phase 3 — Assistant / gateway" (scope + the five exit criteria); `_docs/06-research/002-pii-architecture-plan-pass2.md` §4.1–§4.5 (`pii-net`, egress discipline), §5.1–§5.5 (`pii-memory`, L0–L3, RRF, embedder constraint), §6.2 (pidag subsumed — `after` edges, budget in observable units, delta verification), §8.7 (cron = graphs + timer wheel), §8.8 (approvals), §2.7 (daemon debuggability), §12.2 (dependency DAG), §1.3/§1.4/§1.6 (lints, 450-line gate, CI), §14 Phase 3.

**The load-bearing requirement.** `cargo xtask net-check` must pass: **`pii-net` is the only place in the workspace that opens a socket or resolves a name.** Every byte that leaves or enters this process passes `NetService::authorize()` — which resolves once, pins the `SocketAddr` set, validates address class, refuses mixed answers, and charges the grant (§4.1, §4.3). Phase 2's load-bearing invariant was a dependency edge that must not exist; Phase 3's is a call site that may exist in exactly one crate. Everything else in this phase — channels, workers, memory, cron, approvals — is subordinate to keeping that chokepoint honest, because it is the only thing that makes "the daemon owns sockets" a fact rather than a diagram.

The five phase exit criteria from `001` are behavioural and are all delivered (E21–E24, E12–E17); the chokepoint is the structural invariant that keeps them from being satisfied by a shortcut.

**Scope cuts — stated explicitly, as instructed.**

1. **The gateway is CUT** → `specs/06-phase3b-gateway-mcp.md`. No `axum`, no REST, no WebSocket, no dashboard, no SSE. Reason: none of the five load-bearing exit criteria touch it, the control protocol (`pii-proto`) already serves every client Pii has, and `axum + hyper + tower + http` is the largest new third-party subtree in the whole plan. `pii-obs` stage 2, `pii logs -f`, `pii top`, `pii prof` and pass-2 §14's exit 8 move with it, as does `pii-mcp` (`rmcp` needs HTTP+SSE and a quarantined `reqwest`).
2. **TLS is CUT** → 3b, and with it `https://` egress, remote transport, `pii pair`, bearer tokens, and talking to the real `api.discord.com`. `pii-net` speaks plaintext HTTP/1.1 over TCP. Reason (verified above): the workspace contains **no** TLS stack today, so TLS is a new third-party subtree (`rustls` + `ring`/`aws-lc-rs`, i.e. a C toolchain) that fights pass-1 §0's "no C deps in the default build" and that **no container-local exit criterion can exercise**. Phase 3 therefore ships the whole egress *policy* (grants, resolve-once-pin, class validation, deadlines, byte and connection budgets) and the plaintext transport; 3b adds a `TlsConnector` behind the unchanged `NetService::connect`. Honest consequence: **E15 runs Discord against a Discord-API-compatible fake on loopback**, and the live form (`PII_DISCORD_API_BASE=https://api.discord.com`) is documented in `scripts/phase3/README.md` as blocked on 3b. The `ollama:` provider, by contrast, becomes fully real — local Ollama is plaintext `http://127.0.0.1:11434`.
3. **`hickory-resolver` is CUT.** Resolution is `std::net::ToSocketAddrs` behind a `Resolver` trait, called **exactly once** per authorize. §4.3.2's actual requirement is resolve-once-then-pin, not a particular resolver; the trait keeps hickory a drop-in, and a `StaticResolver` makes the entire egress policy testable with no DNS at all.
4. **`the workspace memory-core` is CUT as a dependency; `pii-memory` is first-party.** §5.1 says "embed, do not reimplement" — unexecutable here: the crate is not vendored and not published to this machine. Consequence: no `tantivy`, no `hnsw_rs`, no `fastembed`/ONNX. `pii-memory` implements pass-1 §6.3 directly: hand-rolled BM25 over redb postings, i8-quantised vectors with a streaming brute-force scan, a co-occurrence graph lane, RRF k=60, temporal decay. §5.5 itself says brute force wins below ~10k docs; HNSW is deferred until a measured corpus exceeds that.
5. **L2 scene *labelling* and L3 persona *generation* are CUT** (both are LLM calls). L2 communities are **computed** by label propagation (§5.2 is emphatic that membership must not be a model's opinion) and labelled deterministically from their top three concepts; L3 is a pinned document written by `memory.put{layer:"persona"}`. The L0–L3 *structure* and the §5.2 retrieval order ship; the two generative triggers do not.
6. **Consolidation's LLM conflict validation is CUT.** §5.4's incident class is made structurally impossible: `consolidate` makes **zero** model calls in this phase. The hard-won constants (`MIN_SHARED_CONCEPTS = 2`, `MIN_CONCEPT_JACCARD = 0.15`, `NEGATION_WINDOW = 8`) and a hard candidate cap ship as the near-duplicate merge rule, with the cap asserted by a test.
7. **The 72 h soak is not an exit criterion; the leak gate is.** No session in this container runs 72 h. `cargo xtask rss-gate` performs the *same measurement* — sample `VmRSS` from `/proc/<pid>/status` every N seconds, assert the **max**, not the mean (`001` is explicit about this) — and the phase gates on a 300 s window plus a **steady-state slope** assertion across 3,000 runs, which is what actually detects the failure mode a 72 h soak detects. The 72 h form is the identical command with `--secs 259200 --interval 60`, documented in `scripts/phase3/README.md` as the pre-release ritual and recorded there when run.
8. **Reactive `wait{Event{topic}}` triggers are CUT** → Phase 4 (§14 gives Phase 4 IoT/reactive). Cron ships, because §8.7's timer wheel is what makes an idle daemon cheap, and E21's RSS budget is meaningless without it.
9. **MQTT, BLE, serial, `ListenSpec::Uds`, WASM `protocol-handler`, `pii-sync`, `pii-mcu`, `pii-hw` are not in this phase** (§14 Phases 4–6).
10. **The control UDS listener stays in `pii-server::uds`** and is not migrated into `NetService`. It is the control plane, it already carries Phase 2's peercred gate and its own exit criteria, and moving it risks a working security boundary for no gain. `NetService::listeners()` reports it for `sys.status`; `net-check`'s allowlist names its two files. This is the one stated exception to the chokepoint.
11. **`pii acp` — planner decision recorded here.** Phase 2 deferred it (HANDOFF caveat 1). It is **cut to `specs/06-phase3b-gateway-mcp.md`**: ACP is a second client of the same protocol and belongs with the other client surfaces, not with the daemon's internals.

**Protocol version bumps to `pii.v2`.** The `Method` and `Event` enums are closed by design (Phase 2 F1.3/F1.7), so adding methods and event kinds is a breaking wire change and must be announced, not smuggled. `PROTOCOL_VERSION` becomes `"pii.v2"`. **This makes one existing test wrong, and updating it is required, not a weakening**: `server::hello_skew_is_hard_refusal` offers `"pii.v2"` as the *bad* version — it must now offer `"pii.v99"` and still assert code `100` with `data.expected == "pii.v2"`. #### W2 — `pii-net`: the one socket

- **F2.1** New crate `crates/pii-net`. Dependencies, exactly: `pii-abi`, `pii-core`, `serde`, `serde_json`, `thiserror`, `parking_lot`. **No `tokio`** — `NetService` is synchronous and thread-based, matching `GraphNode::run`, `ModelProvider::chat` and `HttpTransport` (all sync). Features: `default = []`, `testing = []` (F2.10).
- **F2.2** `src/grant.rs`: `pub struct NetGrant { pub connect: HostScope, pub allow_private: bool, pub max_conns: u32, pub max_bytes_out: u64, pub max_bytes_in: u64, pub expires_at_ms: Option<u64> }` — **no `Default` impl**; a zero value is a downgrade (§4.3). `pub struct HostScope(Vec<HostPattern>)` with `HostPattern::parse("host:port" | "*.suffix:port" | "host:*")`; `*.example.com` matches `a.example.com` and `a.b.example.com` but **not** `example.com`. `pub trait GrantStore: Send + Sync { fn grant(&self, principal: &str, key: &str) -> Option<NetGrant>; fn all(&self) -> Vec<(String, String, NetGrant)>; }` plus `StaticGrants` (a `BTreeMap`). The store-backed impl lives in `pii-server`, so `pii-net` needs no `pii-store` dependency.
- **F2.3** `src/authorize.rs` — the pure decision function, the heart of the phase:
  `pub fn authorize(target: &Target, resolved: &[IpAddr], grant: &NetGrant, now_ms: u64) -> Result<Pinned, NetDenied>` where `Target { host: String, port: u16 }` and `Pinned { addrs: Vec<SocketAddr>, deadline_ms: u64 }`. Rules, in this order:
  1. `grant.expires_at_ms` in the past → `NetDenied::Expired`.
  2. `host:port` not matched by `grant.connect` → `NetDenied::NotAllowed`.
  3. `resolved` empty → `NetDenied::NoAddress`.
  4. Classify every address: `pub enum AddrClass { Public, Loopback, Private, LinkLocal, CloudMetadata, Multicast, Unspecified, Nat64MappedPrivate }`. `CloudMetadata` = `169.254.169.254` and `fd00:ec2::254`. `Nat64MappedPrivate` = `64:ff9b::/96` whose embedded IPv4 is private/loopback/link-local. IPv4-mapped IPv6 (`::ffff:a.b.c.d`) is classified by its embedded IPv4.
  5. **Mixed answers are always refused** → `NetDenied::MixedAnswer`: if the set contains a `Public` address *and* any non-`Public` address, refuse regardless of `allow_private`. A hostname resolving to one public and one private address is an attack, not a config (§4.3.3).
  6. Any `CloudMetadata`, `Multicast`, `Unspecified` or `Nat64MappedPrivate` → `NetDenied::BlockedClass`. `Loopback`, `Private`, `LinkLocal` → refused unless `grant.allow_private`.
  7. `deadline_ms = now_ms + req.timeout_ms` — **one deadline spans authorize + resolve + dial + request + response** (§4.3.4). No per-stage budgets.
  `NetDenied` is `Display` and converts to `PiiError::Denied("net: <reason>: <detail>")`.
- **F2.4** `src/resolve.rs`: `pub trait Resolver: Send + Sync { fn resolve(&self, host: &str, port: u16) -> Result<Vec<SocketAddr>, PiiError>; }`, `SystemResolver` (uses `ToSocketAddrs` — the only name-resolution call site in the workspace), `StaticResolver(BTreeMap<String, Vec<SocketAddr>>)` for tests. **`NetService::connect` resolves exactly once and then dials only `Pinned.addrs`, in order, never re-resolving** (§4.3.2). A test resolver that returns a different answer on its second call must not change the dialled address.
- **F2.5** `src/lib.rs`: `pub struct NetService(Arc<Inner>)`, built by `NetService::new(NetConfig { resolver: Arc<dyn Resolver>, grants: Arc<dyn GrantStore>, clock: Arc<dyn Clock> })`. `Clone` shares the `Arc` — the **connection registry is process-wide and keyed by canonical principal**, so cloning the service cannot multiply a `max_conns` lease (§4.3.5; zeroclaw hit exactly this bug). API: `connect(&self, ctx: &Ctx, target: &Target, key: &str) -> Result<Conn, PiiError>`, `request(&self, ctx: &Ctx, req: &HttpRequest) -> Result<HttpResponse, PiiError>`, `listen(&self, ctx: &Ctx, spec: ListenSpec, proto: Protocol, handler: Arc<dyn HttpHandler>) -> Result<ListenerId, PiiError>`, `close(&self, id: ListenerId)`, `listeners(&self) -> Vec<ListenerInfo>`, `grants(&self) -> Vec<GrantInfo>`, `register_external_listener(&self, info: ListenerInfo)` (how the control UDS socket appears in `sys.status` without moving its bind).
- **F2.6** `src/dial.rs`: the only `TcpStream::connect` in the workspace. Dials each pinned address in order with the remaining deadline, returns the first success, and on total failure returns `PiiError::Unavailable("net: no address reachable for <host>")`. Requires `CapKind::NET` via `ctx.net()?` **before** anything else. Every denial emits `net_denied { target, reason }` on the bus via the observer.
- **F2.7** `src/conn.rs`: `pub struct Conn` wraps the stream and charges the grant: reads add to `bytes_in`, writes to `bytes_out`; exceeding `max_bytes_in`/`max_bytes_out` closes the connection and returns `PiiError::Denied("net: byte budget exhausted")`. `Drop` releases the connection lease. Counters are visible in `GrantInfo`.
- **F2.8** `src/http/codec.rs` — hand-written HTTP/1.1, no dependency:
  - Request: `<METHOD> <path-and-query> HTTP/1.1`, headers `Host`, `User-Agent: pii/0.1`, `Connection: close`, `Content-Length` when the body is non-empty, plus caller headers (caller headers may not override `Host` or `Connection`).
  - Response: status line (reject a non-`HTTP/1.` version), headers until the blank line (ASCII-case-insensitive names, value trimmed, header count ≤ 100, header block ≤ 64 KiB), body by `Content-Length` **or** `Transfer-Encoding: chunked` (chunk-size line, chunk, CRLF, terminating `0`), body cap **8 MiB** → `PiiError::Invalid("http: body too large")`.
  - No redirects (a 3xx is returned verbatim), no cookies, no keep-alive, no compression. Parsing is total: every malformed input is an `Err`, never a panic, never an index-out-of-range.
  - `pub fn parse_url(url: &str) -> Result<(Scheme, Target, String), PiiError>`; `https` → `PiiError::Invalid("https requires the tls feature (Phase 3b)")`.
- **F2.9** `src/http/client.rs`: `impl HttpTransport for NetService` — `parse_url` → `authorize` → `dial` → write request → read response with the shared deadline → `HttpResponse`. Status 429 and 5xx are returned as an `Ok(HttpResponse)`; mapping them to `PiiError::Unavailable` is the *caller's* job (F2.12), because a webhook caller may legitimately want the 503 body.
- **F2.10** `src/listen.rs` + `src/http/server.rs`: `ListenSpec::Tcp { addr: SocketAddr }`, `Protocol::Http`, `pub trait HttpHandler: Send + Sync { fn handle(&self, req: &HttpRequest) -> HttpResponse; }`. One accept thread per listener (non-blocking accept + 20 ms sleep, so `close()` is prompt and no thread is parked forever), one thread per connection, hard-capped by `max_conns` (excess connections get `503` and close). Request body ≤ 1 MiB. The server **always answers and never panics**: a handler that returns an error yields `500` with an empty body. `addr` with port `0` binds an ephemeral port; `ListenerInfo.addr` reports the bound port so tests need no fixed ports.

#### W3 — `pii-worker`: supervision and hot reload

- **F3.1** New crate `crates/pii-worker`. Dependencies: `pii-abi`, `pii-core`, `serde`, `serde_json`, `thiserror`, `parking_lot`. **Not `pii-proto`** — the worker vocabulary is not the client vocabulary and must not be coupled to it.
- **F3.2** `src/frame.rs`: newline-delimited JSON over the child's stdin/stdout. `WorkerFrame` is a closed, tagged enum: `Req { id: u64, op: String, args: Value }`, `Res { id: u64, ok: Option<Value>, err: Option<WorkerErr> }`, `Note { level: String, msg: String }`. `WorkerErr { code: String, message: String }`. Ops: `hello` → `{name, tag, pid, protocol: "pii.worker.v1"}`, `invoke` → the tool result, `info`, `shutdown`. A frame longer than 8 MiB is fatal for that worker (kill + restart). **stderr is drained into `Note`-equivalent log lines and never blocks** — a worker that writes 10 MB to stderr must not deadlock the supervisor.
- **F3.3** `src/spec.rs`: `pub struct WorkerSpec { pub name: String, pub program: PathBuf, pub args: Vec<String>, pub env: Vec<(String, String)>, pub max_in_flight: u32 (default 16), pub ready_timeout_ms: u64 (default 2000), pub restart_backoff_ms: u64 (default 50), pub restart_window_ms: u64 (default 60_000), pub max_restarts_in_window: u32 (default 5) }`. No `Default` for the whole struct — `program` is a security-relevant choice.
- **F3.4** `src/supervisor.rs`: `pub struct Supervisor` with `start(ctx) -> Result<(), PiiError>`, `invoke(&self, ctx: &Ctx, op: &str, args: Value, timeout_ms: u64) -> Result<Value, PiiError>`, `info(&self) -> WorkerInfo`, `reload(&self, ctx) -> Result<ReloadReport, PiiError>`, `shutdown(&self)`. Internals: spawn via `ProcCap::spawn_child`; one reader thread (stdout → demux by `id` into `oneshot`-style slots), one writer thread draining an mpsc, one stderr drain thread. `hello` must answer within `ready_timeout_ms` or the child is killed and the start fails.
- **F3.5** **Death is detected and is retryable.** On reader EOF or a non-zero/killed exit: every in-flight request id is completed with `PiiError::Unavailable("WorkerDied: <name> pid <pid> code <c>")`, the bus gets `worker_died { worker, pid, code, in_flight }`, and the child is respawned after `restart_backoff_ms`, emitting `worker_restarted { worker, pid, restarts, took_ms }`. `took_ms` is measured from death detection to the new child's successful `hello` and **must be < 2000** for E13 (the design target is < 100 ms; the criterion is the ceiling from `001`). More than `max_restarts_in_window` restarts inside `restart_window_ms` moves the worker to `WorkerState::Failed`, and further invocations return `PiiError::Denied("worker '<name>' is failed")` — a crash loop must not become a spawn storm.
- **F3.6** **Hot reload drops nothing.** `reload()`: (1) state → `Draining`, new invocations are **queued** (bounded 256; a full queue returns `PiiError::Unavailable`, which the graph retries) rather than rejected; (2) wait for in-flight to reach zero, deadline 5 s; (3) send `shutdown`, wait for exit ≤ 1 s, else kill; (4) spawn from the **current** `program` path (which the operator has replaced on disk); (5) `hello`; (6) state → `Ready` and drain the queue in FIFO order. `ReloadReport { old_pid, new_pid, drained, in_flight_at_start }`. **No request may be answered with an error caused by a reload** — that is E14, and it is the whole point of the drain queue.
- **F3.7** `pii-server` registers a `worker` node kind (`src/nodes/worker.rs`): cfg `{ worker: String, op: String, args: Value }` where `args` values may be `$.`-expressions (`pii_graph::expr::eval_or_literal`, as the `tool` node already does). Ports `ok`, `err`. Effects `MUTATES_EXTERNAL`; required caps `CapKind::SPAWN`. A `PiiError::Unavailable` from the supervisor propagates **unchanged** so the scheduler's `RetryPolicy` sees `is_retryable() == true` and retries — this is the mechanism E12 asserts end to end.
- **F3.8** `pii worker-exec --name <n> [--tag <t>]` — the reference worker, part of the `pii` binary, speaking F3.2 on stdio. Ops: `echo{v}` → `v`; `sleep{ms}` → `{slept: ms}` (cancellable); `crash` → `std::process::abort()`-equivalent immediate death **without** answering; `info` → `{name, tag, pid}`. It is the fixture for E12/E13/E14 and must not depend on the engine.
- **F3.9** RPCs `worker.list` and `worker.reload` (F1.7/F1.8) plus CLI `pii worker ls` and `pii worker reload <name>`, both going through the protocol (§2.7: no client reads the daemon's files).

#### W4 — `pii-memory`: BM25 + i8 vectors + graph, fused by RRF

- **F4.1** New crate `crates/pii-memory`. Dependencies: `pii-abi`, `pii-core`, `pii-store`, `serde`, `serde_json`, `thiserror`, `parking_lot`. No third-party search, vector or embedding crate (cut 4).
- **F4.2** `pii-store` gains `src/mem.rs`: `pub struct MemStore` opened on a **second redb file** (`memory.redb`), keeping the vector index isolated from the run journal (§5.1: redb's lock is per file). Tables: `mem_doc: &str -> &[u8]`, `mem_term: (&str, &str) -> u32` (`(term, doc_id) -> tf`), `mem_df: &str -> u64`, `mem_vec: &str -> &[u8]` (i8 vector + f32 scale), `mem_edge: (&str, &str) -> u64` (concept co-occurrence counts), `mem_meta: &str -> u64` (`n_docs`, `sum_dl`, `dims`), `mem_archive: &str -> &[u8]`. **redb stays confined to `pii-store`** — `xtask deps-check` gains invariant 5 (F7.3).
- **F4.3** `src/doc.rs`: `Doc { id: String, layer: Layer, kind: DocKind, text: String, concepts: Vec<String>, importance: f32, created_ms: u64, last_used_ms: u64, evidence: Option<(String, u64)>, archived: bool }`; `Layer ∈ L1|L2|L3`; `DocKind ∈ Atom|Scene|Persona|Skill`. Ids are `blake3(text)[..16]` hex, so the same fact put twice is the same doc (idempotent put).
- **F4.4** `src/tokenize.rs`: `tokenize(&str) -> Vec<String>` — lowercase, split on `!char::is_alphanumeric()`, drop tokens shorter than 2 chars, drop a fixed 40-word stoplist declared in the file. No stemming: morphology is the vector lane's job, and that is precisely why the hybrid can beat BM25 (F4.16).
- **F4.5** `src/bm25.rs`: standard BM25, `k1 = 1.2`, `b = 0.75`, `idf = ln(1 + (N - df + 0.5) / (df + 0.5))`, document length from `mem_meta`. `bm25_search(&self, q: &str, k: usize) -> Vec<(String, f32)>` reads postings from `mem_term` — **no in-RAM inverted index**; the RSS budget is why.
- **F4.6** `src/embed.rs`: `pub trait Embedder: Send + Sync { fn dims(&self) -> usize; fn name(&self) -> &str; fn embed(&self, texts: &[String]) -> Result<Vec<Vec<f32>>, PiiError>; }`.
  - `TrigramEmbedder` (**the default, deterministic, offline**): dims 256; lowercase, pad the text with `_`, take character 3-grams, hash each with FNV-1a into `dims` buckets, weight `sqrt(tf)`, L2-normalise. It captures morphology and typos that exact-token BM25 misses, which is a real retrieval gain and not a rigged one.
  - `OllamaEmbedder` — `POST {host}/api/embeddings` through `Arc<dyn HttpTransport>` (no socket code in `pii-memory`).
  - `NullEmbedder` — `dims() == 0`, used to prove the degraded path.
  - Quantisation (`src/quant.rs`): `q[i] = clamp(round(v[i] * 127), -127, 127)` stored with an f32 scale; similarity is an `i32` dot product converted to f32. Round-trip error must stay under 1 % on unit vectors (a test asserts it).
- **F4.7** Vector lane (`src/vector.rs`): a brute-force scan **streaming from `mem_vec` in batches of 512 docs**, holding at most one batch plus a top-k heap in memory, with an LRU cache bounded by `cache_bytes` (default 8 MiB, configurable). No full-corpus resident array — this is the requirement that keeps E21's 50 MB honest at 5,000 docs.
- **F4.8** Graph lane (`src/graph_lane.rs`): `mem_edge` counts concept co-occurrence within a doc. A query's concepts (its tokens that exist as concepts) expand to the top 8 co-occurring concepts, and documents carrying them are scored by summed edge weight. Communities (L2) are computed by **label propagation** over `mem_edge` (deterministic: iterate concepts in sorted order, 10 rounds, ties broken by lexicographic order), and a scene doc is written per community with `text` = the top three concepts joined by `", "`. No model call anywhere in this file.
- **F4.9** Fusion (`src/search.rs`): RRF with `k = 60` over the three lanes (`score += 1 / (60 + rank)`), then temporal decay `score *= exp(-λ * age_days)` with `λ`: atom `0.02`, scene `0.005`, skill `0.001`, persona `0.0` (never decays). `age_days` uses `Ctx::now_ms()`, so decay is table-testable with `FixedClock`. Returns `MemoryHit { doc, score, lanes }` where `lanes` names which lanes contributed — required by E17's per-lane report.
- **F4.10** **Degrade honestly** (§5.3): if the embedder errors or `dims() == 0`, search runs the two remaining lanes, sets `degraded: true` with `lanes: ["bm25","graph"]` in `MemorySearchResult` and `sys.status.memory`, and emits `memory_degraded { lanes, reason }` **once per transition** (not per query). It must never silently return worse results.
- **F4.11** **Vectors are persisted, not memory-resident** — the specific `the workspace memory-core` bug §5.3 names: every `put` writes `mem_vec` inside the same write transaction as `mem_doc`, and every search reads from redb. E18 writes 1,000 docs, reopens the store in a new process, and asserts recall@10 for the vector lane is **identical**.
- **F4.12** `src/consolidate.rs`: `consolidate(&self, ctx: &Ctx, cfg: &ConsolidateCfg) -> Result<ConsolidateReport, PiiError>` — decay refresh, near-duplicate merge, archive. Candidate generation uses the constants ported from the §5.4 incident: `MIN_SHARED_CONCEPTS = 2`, `MIN_CONCEPT_JACCARD = 0.15`, `NEGATION_WINDOW = 8` (a negation token must occur within 8 tokens of a shared concept), and a **hard cap `MAX_CANDIDATES = 200`**: on reaching it, generation stops and `candidates_capped: true` is reported. **Zero model calls.** Merging keeps the higher-importance doc and unions the concepts; the loser is **archived, never deleted** (§5.4: forgetting is the compression step, and archives are recoverable).
- **F4.13** `memory` node kind in `pii-server` (`src/nodes/memory.rs`): cfg `{ op: "search"|"put"|"extract"|"consolidate", … }`. `extract` takes `$.payload.atoms` — an array of `{text, concepts, importance}` produced upstream by an `agent` node with a structured-output prompt — and writes each with `evidence = (run_id, seq)` (L1 built from L0, §5.2). Ports `ok`, `err`. Required caps: `CapKind::MEMORY_WRITE` for `put`/`extract`/`consolidate`, none for `search`.
- **F4.14** `agent` node cfg gains `memory = { enabled: bool (default false), top_k: u32 (default 6), include_persona: bool (default true) }`. When enabled, **before the first provider call** the node retrieves and injects exactly one extra system message: the persona document (if any), then the top-k hits with their doc ids, in RRF order, truncated deterministically at **6,800 characters** (≈1,700 tokens, §5.2's budget; Context Rot is the reason the budget is small). Retrieval happens in prompt assembly, **not as a separate graph node** (§5.2) — a `memory` node exists only for deliberate, author-placed operations.
- **F4.15** RPCs `memory.search`, `memory.put`, `memory.consolidate`; CLI `pii memory search <q> [--top-k N]`, `pii memory put --layer L --text T`, `pii memory consolidate`. All through the protocol.
- **F4.16** `xtask memory-eval --corpus <f> --queries <f> [--top-k 10]`: builds a fresh `MemStore` under `_tmp/phase3/memeval/`, indexes the corpus, and prints exactly four lines — `lane=bm25 recall@10=<x.xxx>`, `lane=vector recall@10=<x.xxx>`, `lane=graph recall@10=<x.xxx>`, `lane=hybrid recall@10=<x.xxx>`. Exit 0 **iff** `hybrid > bm25` strictly **and** `hybrid >= 0.75`; otherwise print `MEMORY-EVAL FAIL: …` and exit 1. Recall@10 is `mean over queries of |relevant ∩ top10| / |relevant|`.
- **F4.17** Fixtures `fixtures/phase3/memory/corpus.jsonl` (**≥ 200 documents** of real domain prose — notes about this project's own subsystems, operations, and preferences; one JSON object per line `{id, text, concepts}`) and `queries.jsonl` (**exactly 20** `{q, relevant: [ids]}`, 1–3 relevant docs each). **Anti-rigging constraints, all machine-checked by a test in `xtask`**: no query string may appear verbatim as a substring of any relevant document; every query must have at least one relevant document that BM25-alone ranks outside the top 10; `bm25` recall@10 on this set must be **≤ 0.65** (printed, so a corpus tuned to make BM25 look bad is visible); and a unit test must assert that with the vector and graph lanes disabled the hybrid ranking is **identical** to BM25 — proving the fusion is doing work rather than relabelling one lane.

#### W5 — the daemon: lifecycle, timer wheel, cron, approvals

- **F5.1** `pii-server` gains `src/daemon/` (`mod.rs`, `config.rs`, `scheduler.rs`, `approvals.rs`, `router.rs`, `status.rs`). `pub struct Daemon` owns the `Engine`, the `NetService`, the worker `Supervisor` map, the channel router, the scheduler and the listener set. `pub async fn run(self, shutdown: ShutdownSignal) -> Result<(), PiiError>`.
- **F5.2** One config file: `pii daemon --config <path.toml>` (default: `<runtime_dir>/pii.toml` when present, else an empty config). Sections: `[net]` (`grants`, `allow_private`), `[[worker]]` (F3.3 fields), `[[channel]]` (`name`, `kind`, `graph`, `poll_interval_ms`), `[memory]` (`path`, `embedder`, `cache_bytes`), `[[cron]]` (`name`, `graph`, `schedule`, `input`). Parsed with the existing `toml` workspace dependency. An unknown key is an **error**, not a warning (`deny_unknown_fields`) — a typo'd grant must not silently become no grant.
- **F5.3** Graceful shutdown: `SIGTERM`/`SIGINT` (tokio `signal` feature) → stop accepting connections, cancel running runs, `shutdown` every worker, close listeners, flush the store, **exit 0 within 2 s**. A second signal aborts immediately with exit 130.
- **F5.4** Panic hook (§2.7): writes `<runtime_dir>/crashes/<now_ms>.json` = `{ts_ms, thread, location, message, run: Option<String>}` **synchronously** before the process dies, then delegates to the previous hook. Installed by `pii daemon` before anything is served. `panic = "abort"` in release does not skip hooks, so this works in both profiles.
- **F5.5** Timer wheel (§8.7): `pii-store` gains table `timer_wheel: (u64, &str) -> &str` (`(fire_at_ms, run_id) -> resume_key`) with `put_timer`, `next_timer`, `take_due(now_ms)`. `Scheduler` holds **one** `tokio::time::sleep_until` on the earliest entry, **rearmed on every insert** — not a poll loop (§8.7 is explicit). Firing is **one redb write transaction** that appends `Resumed` to the journal and pushes the run onto the ready set, so cross-process safety comes from redb's write lock. `Scheduler::wakeups()` exposes a counter for N5's test.
- **F5.6** `timer` node kind (`pii-graph`, a fifth built-in): cfg `{ in_ms: u64 }` **or** `{ cron: "<5 fields>" }`; returns `Outcome::Suspend { reason: SuspendReason::Timer { in_ms }, key: ResumeKey("timer:<run>:<node>:<fire_at_ms>") }`; on resume it takes port `fired`. **The existing `wait` node is not touched** — it blocks a thread by design and Phase 1/2 tests depend on it.
- **F5.7** `src/cron.rs`: a 5-field UTC cron parser (`min hour dom mon dow`) supporting `*`, `n`, `a-b`, `a,b`, `*/n` and any combination, with `pub fn next_after(&self, now_ms: u64) -> u64`. Pure, table-tested (F6 rows). An invalid expression is `PiiError::Invalid("cron: <detail>")` returned from the node factory's `build`, so `pii graph lint` rejects it at V0.
- **F5.8** Cron wiring: for each `[[cron]]` entry the daemon starts one run of the named graph at startup (the graph's entry is a `timer` node with that `cron`), which suspends immediately; when the wheel fires it, the graph body runs to completion and the daemon **starts a fresh run** for the next firing. One run per firing keeps each firing independently traceable in `pii graph trace` — which is the property §8.7 claims over hermes.
- **F5.9** Approvals (§8.8): `gate` node kind in `pii-server` (`src/nodes/gate.rs`), cfg `{ policy: String, prompt: String }`. On dispatch it consults an injected `ApprovalResolver`: if a decision for its deterministic approval id (`blake3(run_id, node_id)[..16]`) exists in the store, it returns `Next { port: "allow"|"deny", value }`; otherwise it returns `Outcome::Suspend { reason: Approval { policy, prompt }, key: ResumeKey("approval:<id>") }`. Because the decision is read from the store rather than from a future, **replay after a daemon restart is deterministic** — this is what makes "a 3-day approval and a 200 ms tool call are the same shape" true.
- **F5.10** `pii-store` gains table `approval: &str -> &[u8]` (`{approval_id, run_id, node, policy, prompt, requested_at_ms, decision: Option<…>, note, decided_at_ms}`) with `put_approval`, `get_approval`, `resolve_approval`, `pending_approvals`. `approve.resolve` writes the decision and appends `Resumed { key, payload_hash }` in one transaction, then continues the run via `pii_graph::resume`. Resolving twice is idempotent (`resumed: false` the second time). Resolving an unknown id is `ErrorCode::NotFound`.
- **F5.11** Events: suspension emits `run_suspended`, resumption `run_resumed`, and a gate additionally emits `approval_requested` / `approval_resolved`. CLI: `pii approve ls`, `pii approve allow <id> [--note N]`, `pii approve deny <id>`.
- **F5.12** `sys.status` is populated per F1.10, including `rss_kb` from `/proc/self/status`. `sys.reload` re-reads the config file and applies it to channels and workers (a worker whose `program` or `args` changed is reloaded per F3.6); it never restarts the process.
- **F5.13** `pii soak --connect <socket> --runs N --graph G [--concurrency C]` — a CLI driver that starts N runs through the control protocol, waits for each terminal, and prints `soak: runs=<N> ok=<n> fail=<n> ms=<total>`. It exists so `rss-gate` can drive real load through a real daemon over the real transport.
- **F5.14** `xtask rss-gate [--secs 300] [--interval 10] [--max-mb 50] [--runs 3000]`: starts `target/debug/pii daemon` with `fixtures/phase3/soak.toml` and a scripted model under `_tmp/phase3/soak/`, runs `pii soak` against it, samples `VmRSS` every `--interval` seconds for `--secs`, then asserts: (a) **max** RSS < `--max-mb` (assert the max, not the mean — `001` says so explicitly); (b) `rss_last - rss_at_10_percent < 2048 KiB` (the steady-state slope — this is the leak detector that a 72 h soak would eventually surface); (c) sample count ≥ `secs/interval - 1`; (d) the daemon is still answering `sys.status` at the end and exits 0 on `SIGTERM`. Prints `rss-gate: samples=<n> max_kb=<n> slope_kb=<n>` and exits 1 with `RSS-GATE FAIL: <which>` on any breach.

```

   ▲                                │ kill -9

                                    │                                        │

                        respawn (<2 s, target <100 ms) ──► worker_restarted   scheduler retries

reload:  Draining ─► queue new invokes (bounded 256) ─► drain in-flight ─► shutdown
```

**Script contracts** (each script exits non-zero on any failed assertion, writes only under `_tmp/phase3/`, and `mv`s a stale scratch dir to `<name>.old-$(date +%s)` rather than deleting it):

- `worker-kill.sh` — starts a daemon with `fixtures/phase3/workers.toml`; starts a run of a graph whose `worker` node calls `sleep{3000}` with `retry.max = 2`; `kill -9`s the worker pid (read from `pii worker ls`); asserts (a) an event `worker_died` names the pid, (b) `worker_restarted.took_ms < 2000`, (c) the run's journal contains `NodeFailed` with `retryable: true` **and** a later `NodeFinished` for the same node, (d) the run terminal is `Success`. This is `001` exit criterion 3, end to end.
- `hot-reload.sh` — starts the daemon with a worker whose `program` is `_tmp/phase3/worker.sh` (a two-line script exec'ing `pii worker-exec --name w --tag a`); launches 200 sequential `worker` invocations through the protocol; mid-flight rewrites `worker.sh` with `--tag b` and calls `pii worker reload w`; asserts **200 successes and zero errors**, `pii worker ls` reports `tag == "b"`, and the pid changed. Replacing the program file *is* the operational form of "replace the binary" — what is under test is the supervisor's drain-and-respawn, and the pid+tag assertions prove a new process from the new file. This is `001` exit criterion 4.
- `discord-e2e.sh` — starts `FakeHttpServer` on an ephemeral loopback port from `fixtures/phase3/discord/routes.json`; starts the daemon with `PII_DISCORD_API_BASE=http://127.0.0.1:<port>`, `PII_DISCORD_TOKEN=TEST`, `PII_DISCORD_CHANNEL_ID=123456789`, `PII_MODEL=scripted:fixtures/phase3/model/assistant.json`, and a `[[channel]]` bound to `starter/assistant`; waits for the reply; asserts (a) the fake recorded a `POST /channels/123456789/messages` whose `content` matches the scripted answer, (b) `pii graph trace <run_id>` prints the full journal including the `agent` node and the terminal, (c) `run_id` came from a `channel_message` event. This is `001` exit criterion 2.
- `cron.sh` — starts the daemon with a `[[cron]]` firing every minute against a trivial graph, uses `PII_TEST_CLOCK_MS` to drive `FixedClock` forward two intervals (the daemon honours it only when set), and asserts exactly two runs exist with distinct run ids and both terminal `Success`.
- `shutdown.sh` — starts the daemon, starts a long run, sends `SIGTERM`, asserts exit code 0 within 2 s and that the control socket is gone.
- `crash.sh` — runs a graph containing a node that panics, asserts a `crashes/*.json` file appears with `location` and `message`, and that the daemon is still answering `sys.status`.
- `secret-scan.sh` — runs the Discord flow with `PII_DISCORD_TOKEN=SUPERSECRETTOKEN`, captures the full event ndjson, `run.trace`, `sys.status` and `channel.list`, and asserts `SUPERSECRETTOKEN` appears in **none** of them and that the `Authorization` header is never logged.

**Not exit criteria, documented in `scripts/phase3/README.md`** — the 72 h soak (`cargo xtask rss-gate --secs 259200 --interval 60`), the live Discord form (blocked on 3b's TLS), and the live model form (`PII_MODEL=ollama:<model>` against a local Ollama). Each has a place in the README to record the date, the command and the observed maximum.

## Guardrails

- Do NOT open a socket or resolve a hostname anywhere except `crates/pii-net/src/{dial,listen,resolve}.rs` — not in a test, not in a fixture helper, not in `xtask`. `pii_net::testing::FakeHttpServer` exists precisely so tests never need one. `cargo xtask net-check` is the gate and it must fail when violated.
- Do NOT add a third-party crate. This phase is deliberately dependency-free: no `axum`, `hyper`, `tower`, `reqwest`, `ureq`, `rustls`, `ring`, `hickory-resolver`, `tantivy`, `hnsw_rs`, `fastembed`, `ort`, `rmcp`. If a task looks like it needs one, the task is out of scope — re-read the cuts.
- Do NOT implement TLS, HTTPS, WebSocket, the gateway, a dashboard, MCP, `pii acp`, `pii logs`, `pii top`, `pii prof`, MQTT, BLE, serial, WASM plugin networking, or `pii-sync`. Their absence is not a gap; it is `specs/06-phase3b-gateway-mcp.md` and Phases 4–6.
- Do NOT let `pii-model`, `pii-channels` or `pii-memory` depend on `pii-net`. They take `Arc<dyn HttpTransport>` from `pii-core`. That is what keeps their tests offline and the DAG (§12.2) intact.
- Do NOT let any crate other than `pii-store` depend on `redb`. `MemStore` lives in `pii-store`, even though `pii-memory` is its only user.
- Do NOT let `pii-proto` gain a dependency, and do NOT let `pii-tui` gain one either — Phase 2's invariants (`deps-check` 1–4) must keep passing untouched.
- Do NOT weaken an existing Phase 1 or Phase 2 test to make a new one pass. The single authorised change is `hello_skew_is_hard_refusal`, which must now offer `"pii.v99"` and assert `expected == "pii.v2"`. Anything else that breaks means the new code is wrong.
- Do NOT modify the `wait` node. Timer suspension is the new `timer` kind. Phase 1 tests depend on `wait` blocking.
- Do NOT make the scheduler a poll loop, a thread-per-timer, or a 60-second tick. One `sleep_until`, rearmed on insert (§8.7).
- Do NOT let `consolidate` — or anything else in `pii-memory` — call a model. Zero model calls in that crate, no exceptions; the §5.4 incident is why.
- Do NOT tune the memory eval corpus to make the gate pass. The anti-rigging test (F4.17) is part of the deliverable, and `memory-eval` prints all four lanes so a rigged corpus is visible in the output.
- Do NOT answer a request with an error because a reload was in progress. Queue it. That is the entire content of exit criterion 4.
- Do NOT retry a dead worker forever: the restart window cap exists so a crash loop cannot become a spawn storm.
- Do NOT construct a `std::process::Command` outside `ProcCap::{run, spawn_child}`, do NOT call `std::fs` from a tool or node (use `Ctx::fs()`), and do NOT call `SystemTime::now` outside `SystemClock`.
- Do NOT log, journal, emit or return a token, API key, or grant credential. The `Authorization` header is never logged; any URL that would carry a credential is redacted to `<redacted>` before it is recorded.
- Do NOT write outside `_tmp/phase3/` for any artifact, socket, scratch store, worker program or log. Never `/tmp`, never `$HOME`.
- Do NOT delete or `rm -rf` anything that existed before the run. Scripts `mv` a stale scratch dir to `<name>.old-$(date +%s)`.
- Do NOT modify `_repos/`, `_docs/`, `AGENTS.md`, `HANDOFF.md`, `.pidag/`, or any file under `specs/`.
- Do NOT run `git commit`, `git add`, `git push`, or create branches. Files only.
- Do NOT exceed 450 effective lines in any file, and do NOT silence a workspace lint with a blanket `#![allow]`. Per-item `#[allow]` with a `// reason:` comment only, and only where this spec names one: `SystemClock`, `ProcCap::spawn_child`, `pii-net`'s three socket files, and `pii-server::uds` / `pii-cli::cmd_daemon` (pre-existing).
